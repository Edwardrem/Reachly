### Safer

- **The allowlist covers each command, not the whole line.**
  - A line is cut at every unquoted `;`, `&&`, `||`, `|`, `&` and newline, and each command must be allowlisted or
    read-only.
  - An entry like `df *` still covers `df -h | grep sda`. It no longer covers `df -h; mv /srv/app /tmp`.
- **Disguised destructive commands are recognised.** These all stop for a person on every host:
  - quoted or backslashed names (`'rm'`, `r\m`);
  - full paths (`/bin/rm`);
  - `$IFS` used as a space;
  - wrappers (`sudo`, `env`, `nice`, `command`);
  - scripts handed to `sh -c`;
  - `find -delete` and `xargs rm`.
- **What can't be read always asks.** On an allowlist host, none of these is auto-allowed:
  - command and process substitution;
  - a command name taken from a variable;
  - shells, `eval` and `source`;
  - inline Python, Perl, Ruby or Node code;
  - `sudo -s`.
- **Read-only hosts accept only plain inspection.**
  - Planted scripts (`./ls`, `/tmp/ls`) are refused, and so are variables like `PATH=` and `LD_PRELOAD=`.
  - Inspection tools given options that write or run something are refused: `sed` `e` and `w`, `awk` `system()`
    and pipes, `sort -o`, `git log --output`, `curl -D`, `ip netns exec`, `date -s`, `ifconfig eth0 down` and others.
  - `curl -s -o /dev/null -w '%{http_code}'` health checks now run there.
- **Allowlisted folders stay folders.** `write_file /srv/app/*` no longer covers paths that climb out with `..`.

### Tests and evidence

- **Guard evasion suite.** A new suite holds 97 attack cases, plus 38 ordinary commands that must still run. The
  guard as it was in 1.1.2 lets 84 of the attacks through.
- **Releases are tested first.** Each release now runs every test on the tagged commit, the live SSH tests
  included, before anything is built or published. It attaches `Reachly-X.Y.Z-tests.txt`, with the result, the
  commit, the workflow run and every test by name.
- **CI summaries.** Each CI run writes its test count to the run's summary page.

### Demo

- **[demo/](https://github.com/Edwardrem/Reachly/tree/main/demo)** starts the demo video's four servers in Docker,
  with the same incident: a full `/var` that breaks checkout on web-01. It writes an import file with the hosts, the
  jump host, the key and read-only modes.
- **`demo/measure.py`** reads Reachly's audit log, or an export of it, and prints a run's elapsed time, commands,
  hosts and decisions. On the recorded demo's data it gives 52 commands on 4 hosts: 18 auto-allowed, 27 approved
  and 7 blocked.
